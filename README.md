## 1. 과정 설계

### 출하자의 질문 두 개로 시작합니다

> “왜 값이 떨어졌나요? 다음 물량은 언제 보내면 좋을까요?”

추석 연휴 뒤 첫 경매(**9/28**)에서 토마토 값이 크게 내린 사례를 다룹니다(5,033 → 3,046원/kg, 반입 25.8 → 76.8t). 하루 동안 원본에서 확인한 숫자와 다음에 지켜볼 조건을 모은 뒤, 마지막 슬라이드에서 이 질문에 다시 답합니다.

### 진행 방식: 설명은 짧게, 실습은 길게

1. **강사 시연:** 실습 파일과 질문으로 강사가 한 번 보여줍니다.
2. **수강생 실행:** 파일을 첨부하고, 내 품목·날짜에 맞게 고친 질문을 실행합니다.
3. **원본 확인:** AI가 낸 숫자 하나를 원본 엑셀에서 직접 찾아 확인합니다.

### 최종 산출물

- 출하자용 **한 장 브리핑**
- **전화 설명**과 **문자 메시지** 초안
- 다음 업무에서 바꿔 쓸 **질문 양식**

### 모듈별 상세

<details>
<summary><b>M1 · AI가 그려준 시세 그래프, 믿어도 될까?</b>: 경매 파일 한 개로 시작</summary>

경매 엑셀로 시세표를 만들고, AI 초안에 숨은 단위 오류·누락 날짜·명절 평균 문제를 원본에서 찾아 고칩니다.

- 출하자의 전화가 왔습니다 → 오늘 완성할 한 장
- 경매 엑셀에서 시세표 만들기 (강사 시연: 파일 01 + 질문 P1)
- **실습 01** 품목을 바꿔 시세표 만들기: 날짜와 가격 단위 찾기
- **실습 02** 표에서 이상한 곳 찾기 (파일 05)
- **실습 03** 원본을 보고 다시 계산하기: `상자 가격 ÷ 상자당 kg = kg 가격`
- 내 AI 결과 확인표
- **Wrap-up** 숫자는 내가 원본으로 확인한다
</details>

<details>
<summary><b>M2 · AI로 우리 법인의 진짜 경쟁력 비교하기</b>: 전체 평균과 같은 조건 비교</summary>

전체 평균가격이 높은 법인이 정말 잘 받은 걸까요? A~E법인을 같은 조건으로 맞춘 뒤 물량을 반영한 평균을 계산합니다.

- 평균가격이 더 높은 법인
- **실습 04** 법인별 가격·물량 그래프 만들기 (파일 02)
- **실습 05** 같은 조건으로 다시 비교하기: 기간·품종·등급·산지·상자당 무게
- 좋은 등급이 많으면 평균은 어떻게 될까?
- 많이 거래된 날을 평균에 반영하기 (물량가중 평균)
- **실습 06** 물량을 반영해 다시 계산하기: 파일 01의 09/24·09/28 원본으로 확인
- **Wrap-up** 같은 조건끼리 비교한다
</details>

<details>
<summary><b>M3 · 소비지 가격으로 시세 판단의 빈칸 채우기</b>: 소매가격과 산지 날씨</summary>

KAMIS와 기상청에서 소매가격과 산지 날씨를 직접 내려받아 경매 자료와 함께 올리고, 첫날을 100으로 둔 지수로 한 화면에 놓습니다.

- 공공 자료에서 소매가격과 날씨 내려받기
- **실습 07** 같은 상품과 단위인지 확인하기: 경매 01 + 직접 받은 KAMIS 소매가격
- 첫날을 100으로 놓으면 보이는 것
- **실습 08** 가격 흐름과 날씨를 한 화면에 놓기
- 그래프가 보여준 사실 한 가지
- **Wrap-up** 외부 요소로 빈칸을 채운다

> 공공 사이트 접속이나 다운로드가 막히면 대체 파일 03(소매)·04(날씨)를 씁니다.
</details>

<details>
<summary><b>M4 · 다음 주 시세, 무엇을 보면 예상할 수 있을까?</b>: 그때의 자료로 판단한 뒤 실제 흐름 확인</summary>

기준일(9/28)까지의 자료만으로 과거 추석 사례와 반입물량 패턴을 찾고, 값이 오를 때·비슷할 때·내릴 때의 조건을 정리합니다. 수요예측은 **그날 경매된 반입물량**을 기준으로 합니다.

- 가격이 움직이던 날로 돌아가기
- **실습 09** 과거에 비슷한 날 찾기: 원본에서 날짜·반입물량·명절 대조 (파일 06, 새 채팅)
- 반입물량으로 다음 경매 미리 보기
- **실습 10** 이후 가격과 맞춰보기
- “이런 조건이면”으로 말하기
- **실습 11** 다음 주에 볼 조건 세 가지: 기준일까지 확인한 사실만 쓰기
- 짝에게 내 판단 근거 말하기
- **Wrap-up** 맞히기보다 조건을 판단한다

<details>
<summary><b>M5 · AI로 출하자에게 보낼 시세 브리핑 만들기</b>: 출하자에게 설명하기</summary>

세 문장 브리핑, 전화 설명, 문자 메시지를 만들고 숫자와 표현을 점검한 뒤, 다음에도 쓸 질문을 저장합니다.

- **실습 12** 내 자료로 한 장 브리핑 만들기: 세 칸을 직접 써서 넣기
- **실습 13** 전화로 말할 문장 만들기: 결과를 짝에게 읽어주기

- **실습 15** 숫자 하나와 표현 하나 점검하기
- **실습 16** 다음에도 쓸 질문 저장하기
- 처음 답변과 최종 답변 비교
- **M5 Wrap-up** 데이터로 출하자에게 설명한다 → **전체 Wrap-up** 근거 있게 답하기까지

## 4. 사이트 사용법

| 키 | 동작 |
|---|---|
| `→` `Space` `PageDown` | 다음 슬라이드 |
| `←` `PageUp` | 이전 슬라이드 |
| `Home` / `End` | 첫 슬라이드 / 마지막 슬라이드 |
| `O` | 전체 슬라이드 목록 |
| `F` | 전체 화면 |

- 실습 슬라이드 오른쪽의 **[수정한 질문 복사]** 버튼으로 내 조건이 반영된 질문을 복사해 AI 채팅에 붙여 넣습니다.

- 결과가 이상하면 새로 묻기보다 다시 요청합니다. 예: “이 숫자가 나온 날짜와 원본 열을 보여 주세요.”

## 6. 로컬 실행과 배포

**로컬에서 열기**

```bash
git clone https://github.com/datathinkinglab/seoulcheonggwa-ai-training.git
cd seoulcheonggwa-ai-training
python -m http.server 8000      # 브라우저에서 http://localhost:8000
```

> `index.html`을 더블클릭해도 열리지만, 일부 브라우저에서는 복사·저장 기능을 쓰려면 로컬 서버로 여는 편이 안전합니다.

**배포:** GitHub Pages가 `main` 브랜치 루트(`/`)를 바로 제공합니다. `main`에 push하면 1~2분 안에 사이트에 반영됩니다.
